# Scanner-AMR7

تطبيق عربي لجرد الأجهزة عبر الكاميرا، مع حسابات مستخدمين وحفظ سحابي معزول لكل مستخدم بواسطة Supabase.

## المزايا

- تسجيل دخول بحسابات ينشئها مسؤول النظام فقط؛ لا يوجد تسجيل ذاتي عام.
- تسجيل دخول وخروج وجلسة محفوظة وآمنة.
- كل مستخدم يرى ويعدّل ويحذف سجلاته فقط عبر Row Level Security.
- مسح الرقم التسلسلي ورقم الأصل بالكاميرا، مع دعم BarcodeDetector وحل احتياطي لـ iOS.
- تصنيف الأجهزة إلى شاشات، وأجهزة PC، وسكانرات، وطابعات، وهواتف Cisco، وأخرى.
- اقتراح موديلات مرتبطة بنوع الجهاز مع السماح بإدخال موديلات جديدة.
- إعادة اقتراح أسماء الموديلات التي سبق للمستخدم حفظها حسب نوع الجهاز.
- اختيار نوع موقع الجرد واسمه عند الدخول، وحفظ الموقع مع كل جهاز وتصديره إلى Excel.
- عرض السجلات في جداول منفصلة وقابلة للطي حسب نوع الجهاز.
- تحديث السجل تلقائياً عند مسح الرقم التسلسلي نفسه.
- تصدير سجلات المستخدم الحالي إلى Excel.
- واجهة عربية RTL تعمل على الجوال وGitHub Pages.

## الإعداد لأول مرة

1. أنشئ مشروعاً في [Supabase](https://supabase.com/).
2. افتح **SQL Editor** وشغّل محتوى `supabase/schema.sql` كاملاً.
3. من **Authentication → Providers → Email** فعّل Email/Password، ثم عطّل **Allow new users to sign up** لمنع التسجيل العام على مستوى الخادم.
4. للإنتاج، اترك **Confirm email** مفعّلاً. أثناء الاختبار فقط يمكن تعطيله مؤقتاً.
5. من **Authentication → URL Configuration** ضع:
   - Site URL: `https://khalbalawi.github.io/Scanner-AMR7/`
   - Redirect URL: `https://khalbalawi.github.io/Scanner-AMR7/**`
6. من **Project Settings → API** انسخ Project URL ومفتاح `anon` أو `publishable` العام.
7. عدّل `config.js` بالقيم العامة. لا تستخدم مفتاح `service_role` في الواجهة أبداً.
8. ارفع الملفات إلى فرع `main` وفعل GitHub Pages من جذر الفرع.

## إنشاء حساب جديد بواسطة المسؤول

1. افتح مشروع Supabase ثم **Authentication → Users**.
2. اختر **Add user → Create new user**.
3. أدخل البريد والرقم السري، وفعّل تأكيد البريد إذا أردت تسليم الحساب جاهزاً مباشرة.
4. لا تضع مفتاح `service_role` في `index.html` أو `config.js`. إنشاء المستخدمين من لوحة Supabase يحافظ على صلاحيات الأدمن خارج الموقع العام.

## ترقية قاعدة بيانات موجودة

إذا كان المشروع يعمل مسبقاً، شغّل ملف `supabase/migrations/20260830_add_device_type.sql` مرة واحدة من **Supabase SQL Editor** قبل نشر الواجهة الجديدة.

ولإضافة موقع الجرد إلى مشروع قائم، شغّل `supabase/migrations/20260901_add_inventory_site.sql` مرة واحدة من **Supabase SQL Editor**.

## الحماية والصلاحيات

- جدول `assets` يحتوي `user_id` مرتبطاً بـ `auth.users`.
- سياسات RLS تطبق على القراءة والإضافة والتعديل والحذف.
- المستخدم غير المسجل لا يملك أي صلاحية على الجداول.
- حذف مستخدم من Supabase يحذف ملفه وسجلاته تلقائياً عبر `on delete cascade`.
- الصفحة نفسها عامة لأنها مستضافة كملف ثابت، لكن التطبيق لا يعرض البيانات دون جلسة، وقاعدة البيانات ترفض أي وصول غير مصرح به.

## إذن الكاميرا

المتصفح يطلب الإذن فقط بعد الضغط على **تشغيل الكاميرا**. الكاميرا تتطلب HTTPS؛ GitHub Pages يوفره تلقائياً. لا يمكن للموقع منح الإذن نيابة عن المستخدم، وإذا رُفض يجب تفعيله من إعدادات المتصفح.

## الملفات

- `index.html`: الواجهة، المصادقة، السكانر، والحفظ السحابي.
- `config.js`: عنوان Supabase والمفتاح العام.
- `config.example.js`: قالب الإعداد.
- `supabase/schema.sql`: الجداول والفهارس والمشغلات وسياسات RLS.
- `supabase/migrations/20260830_add_device_type.sql`: ترقية آمنة لإضافة نوع الجهاز للسجلات الحالية.

## اختبار سريع

شغّل خادماً محلياً بدلاً من فتح الملف مباشرة:

```bash
python3 -m http.server 8080
```

ثم افتح `http://localhost:8080`. الكاميرا تعمل على `localhost` أو HTTPS.
